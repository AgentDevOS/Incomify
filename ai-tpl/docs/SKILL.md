# Stage-Gated Delivery Workflow

## 概述

这是一套五阶段、带人工确认门控的研发交付流程。  
**每个阶段完成后必须暂停，等待用户明确确认后才能继续。**

---

## 阶段定义

### 阶段 1：需求分析 `requirements_analysis`

**你的职责：**
- 理解用户需求，主动提问澄清模糊点
- 分析技术可行性和潜在风险
- 产出 `docs/requirement.md`

**requirement.md 结构：**
```
# 需求文档

## 需求摘要
## 功能范围
## 不在范围内
## 技术约束
## 验收标准
## 风险与未决项
```

**完成后必须说：**
> 📋 需求分析完成，文档已保存至 `docs/requirement.md`。
> 
> **请审阅后告诉我：**
> - `1` — 确认需求，进入原型阶段
> - `2` — 需要调整，请指出修改意见
>
> 在收到确认前，我不会开始原型制作。

---

### 阶段 2：原型 `prototype`

**仅在用户回复「1」或明确确认后开始。**

**你的职责：**
- 制作可视化 HTML 原型（放在 `prototype/` 目录）
- 产出 `docs/prototype.md`（说明页面结构、交互逻辑、API 假设）
- 禁止在此阶段写 `src/` 目录

**完成后必须说：**
> 🎨 原型完成。请在浏览器中打开 `prototype/index.html` 查看效果。
>
> **请体验后告诉我：**
> - `1` — 确认原型，进入开发阶段
> - `2` — 需要调整，请描述修改意见
>
> 在收到确认前，我不会开始正式开发。

---

### 阶段 3：开发与测试 `development`

**仅在用户回复「1」或明确确认后开始。**

**你的职责：**
1. 先制定实施计划（基于 requirement.md 和 prototype.md）
2. 按计划开发 `src/` 下代码
3. 编写自动化测试
4. 运行 lint + test，确保全部通过
5. 整理测试报告

**完成后必须说：**
> ⚙️ 开发与测试完成。测试结果：[通过数/总数]
>
> **请验收后告诉我：**
> - `1` — 验收通过，进入交付阶段
> - `2` — 发现问题，请描述（我会修复后重新测试）
>
> 在收到确认前，我不会开始交付流程。

---

### 阶段 4：交付 `delivery`

**仅在用户回复「1」或明确确认后开始。**

**你的职责：**
- 构建/打包代码
- 产出 `docs/delivery.md`（变更摘要、影响范围、回滚方案）
- 执行部署（如有配置）

---

## 核心规则

1. **禁止跨阶段**：未收到用户确认，绝对不进入下一阶段
2. **禁止预跑**：不要在需求阶段写代码，不要在原型阶段动 src/
3. **确认词识别**：用户说 `1`、`确认`、`approve`、`继续`、`ok` 均视为确认
4. **拒绝词识别**：用户说 `2`、`调整`、`修改`、`不对` 均视为需要修改
5. **状态同步**：确认后运行 `node scripts/workflow/gate.js advance` 推进状态

---

## 快速命令参考

```bash
# 初始化项目
node scripts/workflow/gate.js init "项目名称"

# 查看当前状态
node scripts/workflow/gate.js status

# 用户确认后推进阶段
node scripts/workflow/gate.js advance

# 记录用户反馈（拒绝时）
node scripts/workflow/gate.js reject "需要修改登录页面的颜色"

# 查看当前阶段门控提示
node scripts/workflow/gate.js gate
```
